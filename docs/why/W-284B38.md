## What was asked

The owner wanted the app to work as a Chrome and Edge extension. The decision was made while
building it. This record was written afterwards, from the code and from what was found then.

## What was done and why

Every import of `pdfjs-dist` is pointed at pdf.js's legacy build, and its worker comes from the
legacy build too. The modern build calls functions that only the newest browsers have, such as
`Promise.withResolvers` and `Uint8Array.fromBase64`, and its worker, which does most of the
reading, calls `Math.sumPrecise`. In a browser without them a PDF is expected to fail to open. The
legacy build makes the same calls, but ships the missing functions with it. The extension allows
Chrome 116 and later ([ADR-0021](../adr/0021-browser-extension.md)), far older than the modern
build needs.

## Alternatives rejected

None considered.

## Assumptions

- How a modern-build PDF fails in an old browser was not tried in Chrome 116.
- The legacy build reads books the same way as the modern one. Not compared.
- The legacy build is a little larger and slower than the modern one, and the difference does not
  matter for reading a book. Not measured.

## When to revisit

When every browser that the extension's `minimum_chrome_version` allows has the functions the
modern build uses, or when pdf.js stops publishing a legacy build.
